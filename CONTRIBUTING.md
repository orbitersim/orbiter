# Contributing to Orbiter

Welcome and thank you for considering contributing to Orbiter!

This document is intended to serve as a start point for understanding the expectations set by the maintainers for new
and existing contributors. It is a work in progress document that tracks the consensus reached in [this discussion](https://github.com/orbitersim/orbiter/issues/680)

The use of specific requirement levels (terms like **MUST**, **SHOULD**, **MAY**, and similar) in this document follows the definitions set out in [RFC 2119](https://www.rfc-editor.org/info/rfc2119/).

## Getting help?

If you have any question regarding getting started or reporting bugs, feel free to reach out to us.

Many of the maintainers have a presence on [Orbiter Forum](https://orbiter-forum.com), though often the best way to begin
a conversation will be via the issue tracker as outlined below.

Please do bear in mind that Orbiter is a volunteer project with a fairly small community, and the team are often busy with personal matters. It may be
a while before you get a reply.

## Report a bug

- Check if your bug has already been reported in the [issue tracker](https://github.com/orbitersim/orbiter/issues).
- If you can't find the bug or feature, please open a new issue.

## Making changes to Orbiter

It's a good idea to get familiar with how the simulator is built and get yourself set up with a good working environment.
You can find some guidance on that in [this document](https://github.com/orbitersim/orbiter/blob/main/COMPILE.md), including
an autobuild script.

## Code style and standards

The Orbiter core itself was largely the work of a single developer prior to 2020, and as such has its own particular style.

Contributions **SHOULD** maintain this established style, unless there is good reason to divert from it. Personal
stylistic choices are therefore discouraged in favour of this approach.

## Use of generative AI tools for contributors

This is a big and divisive topic currently and deserves its own section. At the moment the discussion is still taking place on
how the Orbiter project should handle contributions that are wholly or in part generated with these tools.

A consensus has yet to be reached in the discussion, which will inform the guidance set out in this section.

As an already established minimum, contributed code **MUST** be fully understood by the contributor. Orbiter contribution
is a constructive process, but you **MUST** be able to explain the logic in your pull request as necessary for a reviewer
to understand it. This is expected regardless of the consensus on AI tooling above.

Pull requests **MUST** also be kept as small as is practical for the work they contain. Contributors **SHOULD** expect their
pull request will be read by a human being, rather than an LLM, and structure them accordingly.
